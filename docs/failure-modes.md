# AEGIS — Failure Modes

One row per `docs/coverage-matrix.md` ID. Every "what breaks without it" is
written the way the reviewer will ask for it: *"I implemented X, otherwise Y
would happen."* Where a row's file header already makes this case in more
detail, this table is the short form — read the header for the long form.

"How to demonstrate it live" assumes `npm run dev` and the routes in
`README.md`'s route map. Where a row is a registered lab defect, the toggle
lives in the dev-only Lab panel at the bottom of every page.

## Week 1 — Fundamentals

| ID | Concept | What I implemented | What breaks without it | Demonstrate it live |
|---|---|---|---|---|
| W1-01 | JSX/fragments | `FilterStatus` uses `<>…</>` in both ternary branches instead of a wrapping `<div>`. | I implemented a fragment so the ternary's two branches don't force an extra DOM node into a `<p>` — otherwise the browser would silently close the invalid `<p><div>…</div></p>` nesting and the layout would break in a way that doesn't show up in React DevTools. | View source on `/policies`; no stray wrapper div around the "N of M policies" line. |
| W1-02 | Function components & composition | `PolicyRow` inside `PolicyList` inside `PoliciesPage`. | I implemented three separate components instead of one that maps and returns `<tr>` inline, otherwise `PolicyRow` couldn't be independently memoised (W3-D1-01) — memoisation needs a component boundary to bail out at. | `/policies` — the table is `PoliciesPage` → `PolicyList` → many `PolicyRow`. |
| W1-03 | Typed props | `PolicyRowProps`, and one `Policy`/`Claim`/`Quote` type per concept in `types.ts`. | I implemented one shared type per domain concept, otherwise two routes could each declare their own idea of "Policy" and the moment one spells a status `"cancelled"` and another `"canceled"` the status filter returns zero rows with no type error. | N/A — this is a compile-time guarantee; `npx tsc --noEmit` is the demonstration. |
| W1-04 | `useState` primitive | `usePolicyFilters`'s `rawQuery`. | I implemented local state for the search box, otherwise every keystroke would need to round-trip through the URL before the input could show it, and typing would visibly lag behind the keyboard. | Type in the `/policies` search box — it echoes instantly. |
| W1-05 | Object/array state, immutable update | `PoliciesPage.handleSelect` builds a new recents array (`[id, ...prev.filter(...)].slice(0, 5)`). | I implemented an immutable rebuild, otherwise mutating `prev` in place would leave the array reference unchanged and React would skip the re-render entirely — the "Recently viewed" panel would never update. | Click three different policies on `/policies`; the recents panel updates each time. |
| W1-06 | Functional updater | `setRecentIds(prev => …)` in the same handler. | I implemented the functional form, otherwise two policies opened in quick succession (StrictMode double-invokes this handler in dev) would both read the same stale `recentIds` snapshot and the second write would silently overwrite the first. | Click two policy links fast on `/policies`; both end up in "Recently viewed", not just the second. |
| W1-07 | Lazy `useState` initialiser | `useLocalStorage`'s `useState(() => readStorage(key, initialValue))`. | I implemented the lazy `() =>` form, otherwise `localStorage.getItem` + `JSON.parse` would run on *every* render, not just mount — a synchronous storage read on every keystroke in the search box. | Open DevTools Performance while typing on `/policies`; no `localStorage` calls show up per keystroke. |
| W1-08 | List rendering, stable `key` | `PolicyList` keys rows on `policy.id`; same pattern in claims/documents/coverage tables. | I implemented a stable, data-derived key, otherwise React would key by array index and reordering or filtering the list would make React reuse the wrong DOM node for the wrong policy — visible as row content flashing to the wrong values for one frame. | Filter `/policies` down and back up; rows don't flicker or swap content. |
| W1-09 | Conditional rendering | `&&` for the recents panel, ternary in `FilterStatus`, early return in `PolicyList` for the empty state. | I implemented an explicit empty-state branch, otherwise an empty `<tbody>` under a full `<thead>` would render a table that looks broken rather than a clear "no matches" message. | Filter `/policies` to something with zero matches — a message appears, not a bare header row. |
| W1-10 | Event handling | `PolicyFilterBar`'s typed `ChangeEvent<HTMLInputElement>` handlers. | I implemented typed handlers reading `event.target.value`, otherwise an untyped handler could silently pass the whole `SyntheticEvent` where a `string` was expected and the filter would compare a policy status against `"[object Object]"`. | Change any filter dropdown on `/policies` — the table narrows correctly. |
| W1-11 | Controlled inputs | Every field in `QuoteWizardPage`'s steps reads `value` from `useQuoteState()` and writes via `dispatch`. | I implemented controlled inputs, otherwise the draft in state and what's on screen could disagree — the value written to `localStorage` on every change (W2-D3-03/04) would not be what the agent is actually looking at. | Type in `/quote`'s applicant fields, then refresh — the draft persists exactly as typed. |
| W1-12 | CSS Modules, composed class | `PolicyRow.module.css`'s `STATUS_CLASS` map, keyed by policy status. | I implemented a `Record<PolicyStatus, string>` of Module classes, otherwise a plain template-string class like `` `status-${policy.status}` `` would be invisible to CSS Modules' scoping and resolve to nothing — every status badge would render uncoloured. | `/policies` — active/pending/lapsed/cancelled badges are each a different colour. |
| W1-13 | Lifting state up | Filter state lives in `usePolicyFilters` (owned by `PoliciesPage`), consumed by both `PolicyFilterBar` and `FilterStatus`. | I implemented one owner for the filter state, otherwise the filter bar and the "N of M" summary would each need their own copy and could disagree about what's currently filtered. | Change a filter — the result count and the visible rows always agree. |
| W1-14 | Children/slot composition | `Panel` wraps `children`, used for both the filter bar and "Recently viewed". | I implemented one `Panel` with a slot, otherwise every panel-like widget would reimplement its own header/body markup and CSS, and the first one that drifts (a missing shadow token, different padding) makes the console look like several apps stapled together. | Compare the Filters panel and Recently Viewed panel on `/policies` — identical chrome. |

| W2-D2-02 | `useRef` mutable value, no re-render | `useRenewalCountdown`'s `timerRef`/`lastActivityRef`. | I implemented refs instead of state for values nothing on screen displays directly, otherwise `lastActivityRef` as state would re-render the whole policy detail page on every `mousemove` while the mouse simply rests on it. | Move the mouse over a policy detail page — no extra `[render]` logs for unrelated components. |
| W2-D2-03 | `useRef` previous-value pattern | `usePrevious`, consumed by `StickyPremiumSummary`. | I implemented a ref written during render, otherwise the `useState`+`useEffect` version of "previous value" would render the *new* value alongside a not-yet-updated "previous" for one frame, flashing a stale delta on every premium change. | Change sum insured on `/quote` — the "was ₹X" delta is correct immediately, no flicker. |
| W2-D2-04 | `createContext` + Provider | `AuthContext`/`AuthProvider`. | I implemented a shared context, otherwise "current role" would need prop-drilling from `main.tsx` through `App` through `AppLayout` into every page, and `RequireRole` — not a child of any page — would have no way to read it at all. | Switch role in the header — `/underwriting` immediately allows or blocks access. |
| W2-D2-05 | `useContext` consumption | `RequireRole` reads `useAuth()` to gate `/underwriting`. | I implemented a context read at the gate, otherwise the route table would special-case `/underwriting` inline and every future protected route would repeat the same comparison with its own chance to get it backwards. | As agent, visit `/underwriting` directly — redirected to `/`. |
| W2-D2-06 | Context split (state vs. dispatch) | `QuoteStateContext` / `QuoteDispatchContext`. | I implemented two contexts instead of one, otherwise a step that only ever calls `dispatch({type:'NEXT_STEP'})` would re-render on every keystroke in every *other* step, because the provider value's identity changes whenever `state` does. | N/A directly observable without added logging; see `QuoteContext.tsx`'s header for the reasoning — the split is structural, not a runtime toggle. |
| W2-D2-07 | Custom hook + guard throw | `useAuth()` throws when called outside `AuthProvider`. | I implemented a guard throw, otherwise a component rendered outside the provider would silently receive `null` from `useContext` and crash later, deep inside whatever tries to read `.role` off it, with a stack trace pointing at the wrong file. | N/A without deliberately misplacing a consumer; the throw is defensive, not demoed live. |
